# Тестовое задание «Приложение погоды»

В рамках тестового задания нужно реализовать приложение погоды согласно дизайн-макету.

## Требования:
* Сверстать страницу для мобильного приложения, отображающую текущую погоду (синяя секция).
* Не надо делать:
	* верстку для десктопа,
	* панель с недельным прогнозом погоды (белая секция),
	* функционал поиска/смены города,
	* функционал карты.
* Данные должны быть реальными (Открытый API по погоде).
* Гит история должна быть понятна и оформлена в соответствии c [conventional commits](https://www.conventionalcommits.org/en/v1.0.0/#summary).
* Компонент часов должен постоянно показывать актуальное время.
* Цвета должны задаваться через [sass-переменные](./src/common/styles/colors.scss).
* Code Style должен соответствовать репозиторию.
* Использование storybook будет плюсом, но необязательно.

## Инструкция по установке
1. Запустите команду, которая установит зависимости из package-lock файла.
```bash
npm ci
```
2. *(для пользователей Windows)* Убедитесь, что у вас установлен символ окончания строки LF. Для изменения настройки используйте команду:
```bash
git config --global core.autocrlf input
```
3. *(для пользователей VS Code)*. Установите расширение [ESLint](https://marketplace.visualstudio.com/items?itemName=dbaeumer.vscode-eslint) и добавьте в настройки IDE (settings.json) исправление ошибок линтера по сохранению файла:
```json
"editor.codeActionsOnSave": {
	"source.fixAll.eslint": true
},
```
4. *(для пользователей VS Code)*. Установите расширение [PostCSS Sorting](https://marketplace.visualstudio.com/items?itemName=mrmlnc.vscode-postcss-sorting) для сортировки CSS правил. После создания или редактирования CSS-стилей необходимо запускать данное расширение. `F1` -> `PostCSS Sorting: Run`


## Структура проекта

### `/app` — глобальные настройки проекта
Тут лежат глобальные стили. Установка шрифта тоже тут.

### `/common` — папка для всего самого низкоуровненго и общего, необходимого для отображения
Иконки, sass-переменные, вспомогательные функции.

Цвета, миксины и breakpoints тоже тут. Чтобы использоваться их в файле, вставьте вверху файла `@import '@styles';`.

### `/components` — отдельные компоненты
Сюда надо добавлять компонент часов.

### `/pages` — страницы приложения
Тут только одна страница и точка сборки (app). Вся логика страницы должна быть внутри `/city-forecast-page`.

### `/data` — данные приложения
* `api.types.ts` — типы данные, приходящие со стороннего сервиса
* `forecast-service.ts` — сервис, отправляющий запрос на сторонний сервис. Он возвращает ровно то, что получил. Его **можно** менять. Если надо вернуть обработанные данные, то это можно добавить в сервис.
* `/entities` — внутренние данные системы.

### public
Изображения погоды лежат в `public/assets` в формате svg.
